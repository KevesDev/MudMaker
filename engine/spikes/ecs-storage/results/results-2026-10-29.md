## Limitations and handling

- Archetype queries scan the whole archetype list on every call (no query cache). Archetypes held: 9 after building the dataset, 17 while the transient tag is present. Query numbers include that scan.
- Iteration is reported twice. The fresh rows run on a freshly built world where sparse dense order equals creation order. The fragmented rows first apply, untimed and identically on both paths, a seeded destroy and recreate of half the entities and an add and remove of the tag on a tenth, then time iteration. Compare fragmented rows for steady-state behaviour.
- Tag rows are reported twice. Steady-state rows prime the tag untimed (add then remove on the same entities) so storage growth and archetype creation are outside the timed region. Cold-start rows are unprimed and include first-use growth. Latency add tag and add runtime component steps are primed the same way; latency create rows still include amortised container growth, and max values include reallocation.
- CPU placement: thread pinned to logical processor 2 (core 2, efficiency class 1 of a hybrid CPU, top class); process priority HIGH, thread priority HIGHEST
- Per-operation latency uses the invariant TSC (rdtsc and rdtscp with lfence) calibrated against steady_clock, not steady_clock, because steady_clock advances in 100 ns steps and many operations take 10 to 50 ns. Throughput rows use steady_clock.
- AddressSanitizer ran on the correctness tests only. UndefinedBehaviorSanitizer is not available on this MSVC toolchain and did not run. The benchmark itself was not run under any sanitizer.
- Rows flagged as unstable (throughput variance, latency percentile spread above 2.0x between repetitions) are reported as measured. They are compared by median and min-max range, with no rerun and no discarded repetition.
- Git state: DIRTY: 21 files modified or untracked under the spike directory at run start (first: ?? engine/spikes/ecs-storage/.gitignore); the commit hash alone does not identify the measured sources.
- Sparse storage carries an 8 byte component mask per entity and flat sparse arrays; bytes per entity depend on container capacity growth and are not monotonic in entity count.
