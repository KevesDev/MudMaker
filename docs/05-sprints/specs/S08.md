## Phase scope and dispatch

Phase names, deliverables and live statuses are maintained **only in the [S08 sprint tracker table](../../SPRINT-TRACKING.md#s08)**. The Lead selects one small deliverable, an appropriately scoped Builder assignment, the applicable technical contracts, and the verification and independent audit scope **when dispatching**. No universal live demo, hands-on exercise or prewritten negative-test recipe is required for every phase. Actual correctness and safety invariants in the selected contracts remain mandatory.

## Verification and approval

Builder implements the Lead-dispatched scope and runs only focused checks authorized for that work. Lead chooses whether a human walkthrough, automated test, integration run or other direct evidence is appropriate. The independent Auditor checks the assigned scope against the binding contracts and actual evidence; it may investigate risks **within that scope**, without being burdened by a separate tracker-prescribed negative case. Any real defect blocks PASS. Record the Builder commit, sufficient proof and Auditor verdict in the [central tracker](../../SPRINT-TRACKING.md). No blanket full-suite runs; at actual sprint closure only the Lead may explicitly authorize one.

## Lead dispatch contract

`phaseId; allowed source/tests; approved technical contract; one deliverable and non-goals; verification selected by Lead; independent audit scope; evidence; blockers`. Specific tools and test commands are selected using the actual code/test layout at the time of dispatch. Missing owner decisions or research are escalated and marked BLOCKED; neither Builder nor Auditor researches architectural options.

## Client/server boundary and S09C dependency
S08 builds the **safe native MudMaker network gateway**, not the generic third-party Player Client UI. `CommandText/InvokeAction/SubmitText` continue to be authenticated typed messages and never classified by length. The separate [S09C](S09C.md) uses S08's native adapter for MudMaker games and a bounded Telnet/TLS adapter for unrelated MUDs. S08 and S09C share protocol/error test fixtures but **must not share client UI intent handlers with the server CommandService**. [Workspace ownership](../../03-contracts/ui-ux/01-workspaces-and-ownership.md), [Player Client](../../03-contracts/ui-ux/05-player-client-workspace.md). No UX client tab implementation is required to finish S08 network internals.
