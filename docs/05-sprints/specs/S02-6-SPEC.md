# S02.6 SPEC — Graph-paper canvas (S02.6a to S02.6d)

**Binding sources (read, do not invent):** [editor-theme-manager.md](../../03-contracts/editor-theme-manager.md) (Required default: quiet dark graph paper, continuous horizontal and vertical lines, major every `grid.majorEvery`, no dots; pan and zoom in stable world coordinates, viewport-clipped lines aligned to avoid jitter and moire, minor visibility adapts to zoom via token, snap and grid display are independent toggles, HiDPI, keyboard, pen and touch share one world transform), [12 Creator visual spec](../../03-contracts/ui-ux/12-creator-editor-visual-spec.md), [15](../../03-contracts/ui-ux/15-screen-wireframes-and-interaction-states.md) (Create: no selection shows the canvas, not a tutorial), [16 microcopy](../../03-contracts/ui-ux/16-microcopy-and-density-acceptance.md), [02 interaction rules](../../03-contracts/ui-ux/02-interaction-state-and-accessibility.md), `docs/04-features/scripting/02-visual-graph-editor.md` (graph interaction), the grid tokens (`color.graph.grid.minor|major`, `grid.baseStep`, `grid.majorEvery`, `grid.snapStep`, `grid.minorVisibilityMinScreenStep`, `grid.lineWidth`), the S02.5 Create shell `surface` seam. Windows only.
**Write scope:** `app/src/canvas/**` (new), `app/src/editor/**` and `homeDependencies.ts` only to mount the canvas in the Create shell surface slot, `app/src/ui/**` only for an Input Manager surface option, catalog entries for new visible controls, theme tokens only through the S02.1 process.
## Slices
- **S02.6a Viewport transform:** pure world-to-screen math (pan, zoom about a screen point, clamped zoom range from named configuration), stable anchors, HiDPI device-pixel snapping, bounded cost, no drift after long pan/zoom sequences.
- **S02.6b Graph paper renderer:** a canvas element drawing continuous minor and major grid lines (never dots) from the resolved theme tokens (colors read from the ThemeManager snapshot, redrawn on theme change), viewport-clipped, aligned to device pixels, minor lines hidden below `grid.minorVisibilityMinScreenStep`, only drawn lines in view (no whole-world work), `aria-hidden` decorative background semantics where appropriate and an accessible name for the interactive surface.
- **S02.6c Snap and toggles:** snap to `grid.snapStep` in world coordinates (pure function), independent grid-display and snap toggles held in editor state, exposed as catalog controls in the canvas's local strip or View control as doc 12 defines (follow doc 12; do not invent a toolbar), registered actions, keyboard operable.
- **S02.6d Canvas surface:** `GraphViewport` wired to the Input Manager surface API: wheel zoom about the pointer, drag pan (mouse, pen), keyboard pan and zoom (arrows, plus and minus, home to reset) with the same world transform, pinch and touch pan left to S02.7a through the same surface API (declared, not built), focus ring, reduced motion respected (no animated zoom). Mounted in the Create shell's `surface` slot: the Create workspace shows the empty graph paper and nothing else (no nodes, no text beyond the frame row and the toggle controls).
## Acceptance
AC-01 transform math exact for pan, zoom about a point, clamping and HiDPI snapping, with no drift (property-style tests over long sequences); AC-02 renderer draws only continuous lines (test the draw calls with a fake 2D context: no arc or dot primitives, lines aligned, minor hidden below the threshold, major every `grid.majorEvery`), colors only from tokens, redraw on theme change, work bounded by viewport; AC-03 snap and toggles independent and tested; AC-04 wheel, drag and keyboard produce the same transform results through the Input Manager only (no native handlers; text inputs suppress shortcuts); AC-05 both presets, tokens only, no literals; the Create shell inventory is the frame row plus the toggles; AC-06 resize and DPI change handled (ResizeObserver with no loop errors, device pixel ratio change); AC-07 filtered vitest and build green; AC-08 performance: drawing a 4K viewport at the minimum zoom stays bounded by the visible line count (assert the line count formula, no per-pixel work).
