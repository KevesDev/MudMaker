## Phase deliverables and exact handoff
Each phase below is a **small stand-alone vertical slice**. One Builder, then one independently scoped Auditor, with a real hands-on demonstration or runnable harness **before** checkoff. Usually more than one phase should be finishable within a single Claude usage window; if unexpectedly broad, Lead splits the phase in the central tracker *before* assigning it.

**S11.1 SDK build** — Deliver: C#14/.NET10 SDK compile. User test: Build real sample script. Auditor negative case: Bad signature fails.

**S11.2 IPC generation** — Deliver: C++ and C# Protobuf codecs. User test: Roundtrip one hook. Auditor negative case: Bad wire rejected.

**S11.3 Hook manifest** — Deliver: Exact catalog type/mode checks. User test: Bind NPC hook. Auditor negative case: Unknown binding rejected.

**S11.4 Command binding** — Deliver: Host command to C# handler. User test: Run custom salute. Auditor negative case: Remote client can't send code.

**S11.5 ECS effects** — Deliver: Revalidate and commit worker plan. User test: Script unlocks door. Auditor negative case: Illegal effect denied.

**S11.6 Worker start** — Deliver: Load host-published hashed DLL. User test: Worker Ready observed. Auditor negative case: Hash check enforced.

**S11.7 Worker failure** — Deliver: Timeout and crash recovery. User test: Kill during invocation. Auditor negative case: No partial commit.

**S11.8 Persistent fields** — Deliver: Validated ECS/state slot overrides. User test: Restart after lamp change. Auditor negative case: No stale schema.

**S11.9 Graph compile** — Deliver: Typed visual node plan. User test: Run one branch. Auditor negative case: Invalid port blocked.

**S11.10 Graph parity** — Deliver: Same native effect API for code/graph. User test: Compare two executions. Auditor negative case: Equivalent results.

**S11.11 Release activation** — Deliver: Stop/edit/build/publish/restart. User test: New hook active on reboot. Auditor negative case: No mid-live patch.

**S11.12 Two-player demo** — Deliver: Midnight Express gameplay. User test: Alice/Pat complete scenario. Auditor negative case: Reward/phase correct.

## Advanced integration specifics
- Hook catalog and worker source already have **source-level examples**, but compilation/native execution were not demonstrated. Build, run and independently verify them before claims of support.
- Attach the S10 visual command to a locally published C# or typed graph handler and drive from S08 authenticated client. Native ECS rechecks effects; script cannot directly write DB/ECS pointer. A script error must not claim success.
- No player-supplied code, no hot reload, no redesign of C#14/.NET10/Roslyn without owner escalation.

## Build/test rule
Builder selects the **smallest actual source/test modules** touched by this phase, supplies exact commands, logs and a runnable user check. No fabricated test names or simulator standing in for native functionality. Auditor reviews precisely this scope and one failure path; PASS only when evidence is real and blockers/defects are gone. Lead records commit, test, user check and Auditor PASS in [tracker](../../SPRINT-TRACKING.md), then updates the 0/N count. Do **not** run a full-suite test on each phase; full sprint closeout remains Auditor-controlled.

## Handoff contract
`phaseId; existing module/test paths; approved contract; deliverable and non-goals; targeted tests; user demo; negative oracle; evidence links; known blockers`. Research and unresolved decisions must be completed and written into the linked documentation **before** handoff. No 'research how X works' or 'choose a suitable library' Builder task.
