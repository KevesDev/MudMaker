## Phase deliverables and exact handoff
Each phase below is a **small stand-alone vertical slice**. One Builder, then one independently scoped Auditor, with a real hands-on demonstration or runnable harness **before** checkoff. Usually more than one phase should be finishable within a single Claude usage window; if unexpectedly broad, Lead splits the phase in the central tracker *before* assigning it.

**S10.1 Inspector** — Deliver: Schema-driven component editor. User test: Edit and reopen field. Auditor negative case: Type/version enforced.

**S10.2 Blueprints** — Deliver: Reusable template and overrides. User test: Create two different instances. Auditor negative case: Migration safe.

**S10.3 Theme reuse** — Deliver: S09 graph-paper tokens. User test: Switch theme in Blueprint. Auditor negative case: No local hardcoded styles.

**S10.4 Command form** — Deliver: No-code command name/help/action. User test: Create ring bell. Auditor negative case: Invalid action rejected.

**S10.5 Arguments UI** — Deliver: Typed param/switch/multiline controls. User test: Build give lhs=rhs. Auditor negative case: Invalid syntax blocked.

**S10.6 Access UI** — Deliver: Scope/role/quest rule builder. User test: Bell visible at station only. Auditor negative case: No lock bypass.

**S10.7 Alias/help view** — Deliver: Conflict analysis and generated usage. User test: See colliding alias error. Auditor negative case: Cannot shadow logout.

**S10.8 Real test UI** — Deliver: Use native command harness in editor. User test: Try action as two actors. Auditor negative case: No fake PASS.

**S10.9 Command publish** — Deliver: Versioned release validation. User test: Restart with custom command. Auditor negative case: Bad manifest blocked.

## Visual creator acceptance specifics
- Host creates/publishes `CommandDefinition` through typed form for aliases, context, argument codecs, help, access rule and built-in action. All fields map to canonical schema; no second client-side parser or ACL evaluator.
- User demonstrates `ring bell` in real native test world, different outcomes for two actors, and `give "silver key" = "Joe Smith"`. Failed publish shows exact conflict. A beginner should not write code.
- Long roleplay composition is an explicit text operation, not a heuristic for short commands; advanced builder commands can have large typed argument forms. Graph/editor styling comes solely from ThemeManager.

## Build/test rule
Builder selects the **smallest actual source/test modules** touched by this phase, supplies exact commands, logs and a runnable user check. No fabricated test names or simulator standing in for native functionality. Auditor reviews precisely this scope and one failure path; PASS only when evidence is real and blockers/defects are gone. Lead records commit, test, user check and Auditor PASS in [tracker](../../SPRINT-TRACKING.md), then updates the 0/N count. Do **not** run a full-suite test on each phase; full sprint closeout remains Auditor-controlled.

## Handoff contract
`phaseId; existing module/test paths; approved contract; deliverable and non-goals; targeted tests; user demo; negative oracle; evidence links; known blockers`. Research and unresolved decisions must be completed and written into the linked documentation **before** handoff. No 'research how X works' or 'choose a suitable library' Builder task.
