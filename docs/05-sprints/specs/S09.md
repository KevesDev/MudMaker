## Phase scope and dispatch

Phase names, deliverables and live statuses are maintained **only in the [S09 sprint tracker table](../../SPRINT-TRACKING.md#s09)**. The Lead selects one small deliverable, an appropriately scoped Builder assignment, the applicable technical contracts, and the verification and independent audit scope **when dispatching**. No universal live demo, hands-on exercise or prewritten negative-test recipe is required for every phase. Actual correctness and safety invariants in the selected contracts remain mandatory.

## Verification and approval

Builder implements the Lead-dispatched scope and runs only focused checks authorized for that work. Lead chooses whether a human walkthrough, automated test, integration run or other direct evidence is appropriate. The independent Auditor checks the assigned scope against the binding contracts and actual evidence; it may investigate risks **within that scope**, without being burdened by a separate tracker-prescribed negative case. Any real defect blocks PASS. Record the Builder commit, sufficient proof and Auditor verdict in the [central tracker](../../SPRINT-TRACKING.md). No blanket full-suite runs; at actual sprint closure only the Lead may explicitly authorize one.

## Lead dispatch contract

`phaseId; allowed source/tests; approved technical contract; one deliverable and non-goals; verification selected by Lead; independent audit scope; evidence; blockers`. Specific tools and test commands are selected using the actual code/test layout at the time of dispatch. Missing owner decisions or research are escalated and marked BLOCKED; neither Builder nor Auditor researches architectural options.

## UX and machine catalog ownership
This sprint implements Creator Editor UI **only**. Follow [Editor screen contract](../../03-contracts/ui-ux/04-editor-workspace.md) and [Editor controls catalog](../../../contracts/ui/v1/editor-controls.v1.json) filtered to `editor.blueprint`, `editor.inspector`, `editor.commands`; reused widgets from S02 SharedUI. Built-in **no-code host CommandDefinition editor** is NOT the Player Client's local alias/trigger manager (owned separately by S08). A creator's `ring bell` command goes into a published host asset; a player's custom `look` hotkey is local per-profile input. Both must have stable action/tooltip/test IDs and no duplicated parser/ACL or theme manager.
