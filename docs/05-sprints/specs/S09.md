## Phase deliverables and exact handoff

**SharedUI is not Editor game logic.** Shared primitives, theme and focus logic come from [common state contract](../../03-contracts/ui-ux/02-interaction-state-and-accessibility.md) and [ThemeManager scope contract](../../03-contracts/ui-ux/03-theme-and-preferences.md); Editor navigation from [Editor specification](../../03-contracts/ui-ux/04-editor-workspace.md). Rendered controls correspond to [machine inventory](../../../contracts/ui/v1/INDEX.md). Player Client is a separate S09C sprint.

| Phase | Exact small deliverable | Hands-on proof | Auditor negative path |
|---|---|---|---|
| S09.1 | Button/Field/Dialog/DockPanel with action descriptor | change widget state in harness | no missing label or direct service import |
| S09.2 | Central scoped ThemeManager and Editor/Client preview | change one token, check both scopes | one theme library, separate persisted preferences |
| S09.3 | Theme settings/import/export/rollback | import custom Editor theme, restart | bad file preserves prior |
| S09.4 | Editor shell tabs/panels/focus/undo isolation | open Map and Blueprint | code input cannot trigger map action |

| S09.6 | Select/edit map cells and room inspector | paint room and reopen project | stable room identity |
| S09.7 | Accessible tablet toolbar/dock/pen/pinch | edit map without mouse/hover | no accidental pan-as-paint |
| S09.8 | UI registry parity and Editor walkthrough | every visible action discoverable | no orphan action or hardcoded colors |

**Phase gate:** one Builder and one independent scoped Auditor per phase, with evidence only in [single tracker](../../SPRINT-TRACKING.md). Each phase intentionally produces a narrow demonstrator; several can fit one usage session. Owner resolves unknowns before dispatch.

## Build/test rule
Builder selects the **smallest actual source/test modules** touched by this phase, supplies exact commands, logs and a runnable user check. No fabricated test names or simulator standing in for native functionality. Auditor reviews precisely this scope and one failure path; PASS only when evidence is real and blockers/defects are gone. Lead records commit, test, user check and Auditor PASS in [tracker](../../SPRINT-TRACKING.md), then updates the 0/N count. Do **not** run a full-suite test on each phase; full sprint closeout remains Auditor-controlled.

## Handoff contract
`phaseId; existing module/test paths; approved contract; deliverable and non-goals; targeted tests; user demo; negative oracle; evidence links; known blockers`. Research and unresolved decisions must be completed and written into the linked documentation **before** handoff. No 'research how X works' or 'choose a suitable library' Builder task.
