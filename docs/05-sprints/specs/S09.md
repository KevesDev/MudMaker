## Phase deliverables and exact handoff
Each phase below is a **small stand-alone vertical slice**. One Builder, then one independently scoped Auditor, with a real hands-on demonstration or runnable harness **before** checkoff. Usually more than one phase should be finishable within a single Claude usage window; if unexpectedly broad, Lead splits the phase in the central tracker *before* assigning it.

**S09.1 Central ThemeManager** — Deliver: Typed theme schema, one token resolver and shared visual harness. User test: Change typography/color token once; several panes update. Auditor negative case: Auditor checks no hardcoded consumer styles.

**S09.2 Theme customization** — Deliver: Dark default plus save/import/export/preview/rollback. User test: Make custom theme, restart editor and reopen it. Auditor negative case: Auditor tests malformed imports, persistence, contrast.

**S09.3 Graph-paper renderer** — Deliver: Continuous minor/major square grid lines, pan/zoom/snap. User test: Pan/zoom dark graph paper; never dots. Auditor negative case: Auditor tests transforms, clipping and HiDPI.

**S09.4 Editor shell/input** — Deliver: Responsive panels, keyboard/touch/pen/focus management. User test: Use inspector and search on desktop/tablet. Auditor negative case: Auditor checks focus and accessibility.

**S09.5 Map authoring** — Deliver: Real room/cell/region/exit editing with undo and save. User test: Paint and connect rooms, then reopen saved project. Auditor negative case: Auditor checks asset roundtrip and invalid exits.

**S09.6 Visual acceptance** — Deliver: Cross-editor theme consistency + measured UI responsiveness. User test: Creator follows hands-on flow without instructions. Auditor negative case: Auditor independently checks usability/performance.


## Build/test rule
Builder selects the **smallest actual source/test modules** touched by this phase, supplies exact commands, logs and a runnable user check. No fabricated test names or simulator standing in for native functionality. Auditor reviews precisely this scope and one failure path; PASS only when evidence is real and blockers/defects are gone. Lead records commit, test, user check and Auditor PASS in [tracker](../../SPRINT-TRACKING.md), then updates the 0/N count. Do **not** run a full-suite test on each phase; full sprint closeout remains Auditor-controlled.

## Handoff contract
`phaseId; existing module/test paths; approved contract; deliverable and non-goals; targeted tests; user demo; negative oracle; evidence links; known blockers`. Research and unresolved decisions must be completed and written into the linked documentation **before** handoff. No 'research how X works' or 'choose a suitable library' Builder task.
