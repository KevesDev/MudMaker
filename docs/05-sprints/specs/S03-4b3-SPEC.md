## Concrete ownership and approved OS design

- Build real `mudmaker-engine.exe` (CMake target mudmaker-engine) around the SAME b2 factory/ControlSession. Main thread constructs actual World and executes all requests; no second dispatcher, registry, state, writer thread or fake readiness. Native executable is allowed; no standalone Tauri package build. Add only native Win32 transport/entrypoint and actual-process tests.
- Parent owns one pre-created/listening local byte-mode named-pipe server. Name exactly `\\.\pipe\MudMaker.EngineControl.v1.` plus canonical random nonzero GUID; one instance, FIRST_PIPE_INSTANCE, OVERLAPPED, PIPE_REJECT_REMOTE_CLIENTS, protected DACL allowing only current logon SID (restricts current user/session; no Everyone/Anonymous/default ACL). Parent gets connecting client PID and checks actual launched child BEFORE Hello. b3 uses a real test parent; c implements actual Rust parent, so server security here is test-parent proof, not a completed shell feature.
- Child opens that pre-existing endpoint once with overlapped I/O, no reconnection/replay/fallback/network socket. Reject other/remote paths. Open/retain expected parent's SYNCHRONIZE/query-limited process handle before connection, confirm alive, use GetNamedPipeServerProcessId to match expected parent and monitor that retained handle while idle/read/write. Parent must have created pipe before launch; missing/busy endpoint is startup failure, no busy retry loop. Holding parent handle prevents PID reuse confusion.
- Pairing secret remains fresh BCrypt-generated32bytes, never argv/environment/logs/webview. **Approved inherited bootstrap handle representation:** anonymous pagefile-backed mapping containing32bytes, populated by parent; only a READ-ONLY duplicate is inheritable. Child maps FILE_MAP_READ for32bytes, copies to b2 PairingToken, unmaps/closes immediately. No disk/named bootstrap file, writable child mapping or alternate control transport. Parent uses extended startup HANDLE_LIST (only read-only mapping and required diagnostic std handles), CREATE_NO_WINDOW, and erases token/writable mapping after handshake or failure. Session erases its credential after validation. Same-user hostile-process sandbox is not claimed.
- Exact CLI: `--pipe-name <local name> --parent-pid <positive uint32> --bootstrap-handle <valid uintptr decimal> --wire-policy <absolute local drive path> --runtime-policy <absolute local drive path>`. Each flag exactly once, reject unknown/missing/invalid/duplicate flags, no implicit path/secret fallback. No secret-bearing flags. No raw argv/payload logging. No arbitrary webview-controlled launch path/flags in c.

## Timing, framing and lifecycle

Extend RuntimeSettings additively at fields8–13 and runtime-policy.json with named settings: connect_timeout_ms8=10000 (parent launch/connect wait), hello_timeout_ms9=10000, frame_io_timeout_ms10=5000, cancel_drain_timeout_ms11=1500, process_exit_timeout_ms12=5000, pipe_buffer_bytes13=65536. Positive finite Win32-wait-compatible values, checked conversion; no INFINITE-valued knob, pipe buffer<=frame bound. These are configurable local liveness/granularity controls, not performance claims. Existing native configuration loader remains sole parser. No pin/policy-file/frozen-descriptor/worker change. Process config additions do not alter logical value depth32/physical100 or existing session validation.

Use one absolute deadline across each partial frame/write, not reset per fragment. Before first Hello, first byte is bounded by Hello deadline. **After Ready, ordinary idle has no frame timeout:** wait on first byte AND parent handle; only arrival of first byte starts frame deadline for remaining prefix/body. Thus idle app does not lose its World. Read four-byte big-endian length and validate positive/bounded size BEFORE payload allocation; keep full codec parse/representation/pairing gating. Reuse a single codec-owned prefix-length helper if required instead of an alternate framing parser. Expose minimal authoritative `ControlSession::ready()` read if needed; no parallel session-state mirror.

Before Ready, partial-frame deadline is also capped by the original Hello deadline; receiving a first byte cannot extend handshake indefinitely.

Overlapped operations wait on completion/retained parent and deadline; handle partial reads/writes and EOF. On timeout/parent death, CancelIoEx then drain completion BEFORE releasing/reusing OVERLAPPED/event/buffer. Cancellation can complete normally or aborted: inspect actual completion, not cancel return alone. Bound drain with configured budget; if kernel I/O cannot be drained, fail-stop this owned child rather than release pending memory or hang indefinitely. No FlushFileBuffers/unbounded synchronous read/flush or busy polling. No wait/network/thread per game object.

Feed each complete frame through SAME b2 session. Ack occurs only after real bootstrap/Hello. On graceful Shutdown flush final reply via bounded WriteFile completion (not blocking FlushFileBuffers), close and exit0. Malformed/truncated/oversized frame, pairing rejection, lost parent, EOF, timeout or native I/O error exits nonzero with static bounded phase/code/platform diagnostic on stderr and no token/payload. A committed reply whose delivery fails is Unknown client outcome; no rollback/replay claim. Session/OS handles/views/events clean on normal/error paths; test teardown tracks and stops only created child/helper handles, no name-wide kills. Parent death must terminate native child without relying on a kill-on-close job in that acceptance case.
