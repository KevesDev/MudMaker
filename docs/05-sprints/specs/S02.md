## Hardware recommendations in model selection

When the wizard opens, assess **every model in the fixed catalog** against the user's detected CPU/architecture/instruction support, available RAM, available disk space, and configured Host memory/CPU limits. Display a recommendation state beside every model in the selection list; do not hide nonrecommended models. **The same state and plain-language reason must appear prominently inside that model's info panel when opened**, whether the model is recommended or not. Include the measured resources and the model's estimated requirements, and distinguish **Recommended**, **Not recommended (likely slow/resource-intensive)**, and **Incompatible/unavailable**. A recommendation is an estimate, not a guarantee of measured performance. Warn clearly before optional installation of a nonrecommended but technically compatible model; block unsupported architectures or insufficient disk space instead of attempting a broken installation. Recalculate when hardware/budgets change and keep badges and detail text consistent. Users can inspect any model before choosing, without downloading it.

**User verification (S02.10, S04.17):** open the info panel for a recommended model and verify a positive explanation; open a nonrecommended model and verify a clear negative explanation; test the incompatible state; adjust simulated hardware fixtures for tests and confirm the actual running app reflects real detected hardware. The info panel must never incorrectly label a model recommended because it was selected or installed.
