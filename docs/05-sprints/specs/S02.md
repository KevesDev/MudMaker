## Phase deliverables and exact handoff
Each phase below is a **small stand-alone vertical slice**. One Builder, then one independently scoped Auditor, with a real hands-on demonstration or runnable harness **before** checkoff. Usually more than one phase should be finishable within a single Claude usage window; if unexpectedly broad, Lead splits the phase in the central tracker *before* assigning it.

**S02.1 Identity allocator** — Deliver: World scoped entity generations. User test: Create/delete/recreate. Auditor negative case: Stale ID rejected.

**S02.2 Component schema** — Deliver: Typed component registry. User test: Add light component. Auditor negative case: Invalid field blocked.

**S02.3 Mutation API** — Deliver: Writer-only field mutation. User test: Toggle door property. Auditor negative case: No raw write bypass.

**S02.4 Query API** — Deliver: Bounded entity query. User test: Find room occupants. Auditor negative case: Invalid iteration fails.

**S02.5 Revision guard** — Deliver: ExpectedVersion write checks. User test: Competing updates conflict. Auditor negative case: No lost updates.

**S02.6 Event commit** — Deliver: Atomic state plus domain event. User test: Observe one event on change. Auditor negative case: Rollback emits nothing.

**S02.7 Core harness** — Deliver: Lifecycle tests and metrics. User test: Run small ECS sample. Auditor negative case: Real regression checks.


## Build/test rule
Builder selects the **smallest actual source/test modules** touched by this phase, supplies exact commands, logs and a runnable user check. No fabricated test names or simulator standing in for native functionality. Auditor reviews precisely this scope and one failure path; PASS only when evidence is real and blockers/defects are gone. Lead records commit, test, user check and Auditor PASS in [tracker](../../SPRINT-TRACKING.md), then updates the 0/N count. Do **not** run a full-suite test on each phase; full sprint closeout remains Auditor-controlled.

## Handoff contract
`phaseId; existing module/test paths; approved contract; deliverable and non-goals; targeted tests; user demo; negative oracle; evidence links; known blockers`. Research and unresolved decisions must be completed and written into the linked documentation **before** handoff. No 'research how X works' or 'choose a suitable library' Builder task.
