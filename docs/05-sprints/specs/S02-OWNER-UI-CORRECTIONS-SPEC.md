## Required behavior and contracts

1. Selecting a theme in Settings from Splash, Create, Play or Host applies that selection to the entire app immediately and persists it for restart. Internal theme scopes may retain their preset-specific token definitions (for example terminal colors), but Settings must not independently select a different preset per workspace. Use the existing ThemeManager as one authoritative app-level operation: validate all affected scope updates before committing, reject without partial mutation, and publish through the existing observable path. Preserve legitimate custom-theme preview/cancel/save behavior and no preference writes from preview. Do not silently discard existing custom data while reconciling legacy scoped preferences; report the concrete compatibility strategy before implementation. Avoid creating a new theme library or unrelated preferences redesign.
2. Settings is a real hierarchical menu: Settings > Appearance > theme names. Appearance is a submenu opener, not a labelled group with theme rows in the parent Settings popup. Customize Theme and relevant existing appearance controls belong inside Appearance. Other registered settings remain grouped by actual purpose and discoverable; do not invent future panels or duplicate theme rows at root. Nested menus work by pointer, touch and keyboard; selecting a theme closes menus, Escape restores appropriate focus, and opening Appearance does not choose a theme. No ordinary labelled-button tooltips.
3. Create's View menu has one `Output` entry for the existing shared bottom output panel. The panel retains Problems, Test Output, Execution Trace and Build Logs as its internal views, with their actual active content selection. Remove the four redundant View entries. The panel starts closed; explicit Output opens it with its existing/remembered active view (Problems on first open), with a clear close/toggle path. Preserve real diagnostics navigation and later backend wiring; no fake output/status.
4. View > Inspector explicitly opens the right Inspector panel even without a selected object, and can close/toggle it consistently. Automatic contextual opening may still depend on selection; an explicit visibility command must not silently do nothing. Show only real registered inspector chrome/current fields; no fake object, fake selection, tutorial or unavailable message. Existing selection-driven fields still belong to the existing Inspector owner and must not be duplicated.
5. Update current UI docs and catalog metadata to remove contradictions: ThemeManager contract, UI 03, 10, 12–15 and relevant catalogs/index. Mark superseded scoped-selection expectations in prior specs/reports as historical, not current acceptance. Keep sprint tracker counts unchanged for this correction. Lead owns INDEX/tracker/history/handoff and this spec; Builder updates affected technical/UI contracts and catalogs.

### Approved compatibility and custom-theme contract

An explicit global selection in `app.global` wins on preference restore. Legacy data without it chooses the existing home preset, falling back deterministically to editor/client/host when absent or invalid; log disagreement rather than silently treating mixed selections as current behavior. Preserve the original scoped preset/custom/override inputs in one bounded versioned legacy backup inside the existing preference owner before first destructive reconciliation. Do not grow a history, discard old documents silently or introduce a theme-library subsystem. Test the migration and a second restore so the backup is not overwritten.

Custom shared-token edits also Preview/Save app-wide. Unchanged preset-specific scoped token definitions remain internal. Apply changed shared keys across all scopes that own them; scope-only keys apply only where valid. Stage/validate all affected snapshots before publishing. Use the existing ThemeManager and preference representation with one global customization meaning, not a parallel manager/store. Cancel/Escape/unmount restores all scopes and never persists the preview; a rejected edit leaves every scope unchanged. The UI must not expose an undocumented workspace-only customization path.
