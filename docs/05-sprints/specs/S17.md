## Phase scope and dispatch

Phase names, deliverables and live statuses are maintained **only in the [S17 sprint tracker table](../../SPRINT-TRACKING.md#s17)**. The Lead selects one small deliverable, an appropriately scoped Builder assignment, the applicable technical contracts, and the verification and independent audit scope **when dispatching**. No universal live demo, hands-on exercise or prewritten negative-test recipe is required for every phase. Actual correctness and safety invariants in the selected contracts remain mandatory.

## Verification and approval

Builder implements the Lead-dispatched scope and runs only focused checks authorized for that work. Lead chooses whether a human walkthrough, automated test, integration run or other direct evidence is appropriate. The independent Auditor checks the assigned scope against the binding contracts and actual evidence; it may investigate risks **within that scope**, without being burdened by a separate tracker-prescribed negative case. Any real defect blocks PASS. Record the Builder commit, sufficient proof and Auditor verdict in the [central tracker](../../SPRINT-TRACKING.md). No blanket full-suite runs; at actual sprint closure only the Lead may explicitly authorize one.

## Lead dispatch contract

`phaseId; allowed source/tests; approved technical contract; one deliverable and non-goals; verification selected by Lead; independent audit scope; evidence; blockers`. Specific tools and test commands are selected using the actual code/test layout at the time of dispatch. Missing owner decisions or research are escalated and marked BLOCKED; neither Builder nor Auditor researches architectural options.

## Separate host controls and player experience
Only [Host Operations](../../03-contracts/ui-ux/01-workspaces-and-ownership.md) can start/stop releases, change firewall/limits, export security logs or restore backups; render through [Host controls catalog](../../../contracts/ui/v1/host-controls.v1.json). The user joins through **independent S08 Player Client**, not an Editor inspector or embedded host admin console. Host UI uses shared ThemeManager tokens while preserving distinct host permission/preferences. Third-party MUD connections work without starting a local MudMaker server. Test malicious remote host metadata never displays/admin-invokes `host.stop` or `editor.publish`.

## No public-host shortcut
S07.1 is a loopback development host, and S08.6 is local play only. S17 independently proves safe, user-managed public hosting: validated releases, real remote joins, durable restart, hardening, backups and operation. Neither earlier gate counts as completing S17. [Roadmap](../INDEX.md).

## Cross-platform packaging gate

Use [canonical architecture OS matrix](../../02-architecture/architecture-decisions.md#platform-and-packaging-contract). For each advertised OS, install the Creator/Player/Host without C++ toolchain, Node, Python, external database or .NET SDK; include necessary supervised runtime libraries. Verify signed/hardened packaging where platform policy requires, safe native worker process isolation, TLS and firewall guidance, clean uninstall and backup preservation. Windows/Linux are initial desktop host targets; macOS arm64 remains target until full binary/sandbox/persistence suites pass. Test remote tablet flows against a real host, not an embedded tablet engine.
