# S02.7 SPEC — Responsive input (S02.7a to S02.7d)

**Binding sources (read, do not invent):** [02 interaction rules](../../03-contracts/ui-ux/02-interaction-state-and-accessibility.md) (Focus and keyboard, Sizing and accessibility: tablet drawers, hit sizes from tokens, no hover-only or right-click-only commands), [04 editor workspace](../../03-contracts/ui-ux/04-editor-workspace.md), [12 Creator visual spec](../../03-contracts/ui-ux/12-creator-editor-visual-spec.md), [15 wireframes](../../03-contracts/ui-ux/15-screen-wireframes-and-interaction-states.md), [10 shared language](../../03-contracts/ui-ux/10-visual-language-and-shared-shell.md), [editor-theme-manager.md](../../03-contracts/editor-theme-manager.md) (keyboard, pen and touch share one world transform), CLAUDE.md architecture test 7 (centralized Input Manager). Existing: Input Manager `registerSurface` (mouse, touch, pen streams), `registerKeys`, GraphViewport, TabStrip, SplitView, DockPanel (tablet overlay), tokens `interaction.pointerHitSize`, `interaction.touchHitSize`, `layout.tabletWidth`. Windows only (touch and pen on Windows tablets and laptops).
**Write scope:** `app/src/ui/input/**`, `app/src/canvas/**`, `app/src/editor/**`, `app/src/nav/**`, `app/src/frame/**`, CSS and tests for those, theme tokens only through the S02.1 process, catalog entries only for new visible controls.
## Slices
- **S02.7a Touch gestures:** through the Input Manager surface API only: one-finger drag pans the canvas, two-finger pinch zooms about the pinch center with simultaneous two-finger pan, tap activates, long press opens help or the context action already defined by the Input Manager rules (no new menus), plus touch reorder of tabs by long press then drag (the deferred item from S02.5b). Gesture recognition is one shared recognizer (state machine) in `app/src/ui/input/` consumed by the canvas and tabs, with named thresholds from configuration; browser default touch actions disabled only on the surfaces that own the gesture (`touch-action`), pointer capture and cancel handled, no stuck gesture on cancel, blur or a third finger.
- **S02.7b Pen input:** pen draws no strokes yet; it behaves as a precise pointer (drag pan on the canvas with the pen, hover without side effects, barrel and eraser buttons ignored unless a feature registers them), palm rejection: touch contacts are ignored while a pen is in range or down, for a named grace interval from configuration.
- **S02.7c Keyboard workspace navigation:** region cycling with F6 and Shift+F6 across the Create shell regions in the documented order (toolbar, assets drawer when open, canvas, inspector when shown, tabs when shown), each region focusable with a visible focus ring and a landmark role and name; focus returns to the previously focused control in a region; the shortcuts register through the Input Manager scopes, are suppressed in text entry, and conflicts are reported by the existing per-scope check. Play and Host shells get the same cycling over their regions as they exist (frame row and surface).
- **S02.7d Tablet layout:** below `layout.tabletWidth` or with a coarse primary pointer: the inspector and drawers are overlay drawers (existing DockPanel behavior), toolbar menus and controls use `interaction.touchHitSize` hit areas (hit area grows without changing the visual size beyond tokens), the Go To and Settings menus are touch operable with one-tap open and dismiss, no hover-only action anywhere, and no permanently off-screen inspector. Verified by tests that evaluate the real CSS rules and token values (no jsdom layout claims).
## Acceptance
AC-01 gesture recognizer state-machine tests (pan, pinch, pinch+pan, tap, long press, long-press drag reorder, cancel, third finger, blur) with synthetic pointer event sequences; AC-02 canvas results from touch and pen equal those from mouse and keys for equivalent motions (same transform); AC-03 palm rejection grace behavior; AC-04 F6 cycling order, focus restore, text-entry suppression, scope conflicts; AC-05 hit areas and drawer behavior at tablet width from the real CSS and tokens; AC-06 only the Input Manager owns pointer and key streams (style scan: no native handlers in canvas, editor, nav, frame); AC-07 tokens only, both presets, no literals; no tooltips on ordinary controls; AC-08 filtered vitest and build green.
