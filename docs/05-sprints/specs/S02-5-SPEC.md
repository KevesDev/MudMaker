# S02.5 SPEC — Editor shell building blocks (S02.5a to S02.5d)

**Binding sources (read, do not invent):** [12 Creator visual spec](../../03-contracts/ui-ux/12-creator-editor-visual-spec.md), [15 wireframes](../../03-contracts/ui-ux/15-screen-wireframes-and-interaction-states.md) (Create), [10 shared language](../../03-contracts/ui-ux/10-visual-language-and-shared-shell.md), [16 microcopy](../../03-contracts/ui-ux/16-microcopy-and-density-acceptance.md), [02 interaction rules](../../03-contracts/ui-ux/02-interaction-state-and-accessibility.md), [04 editor workspace](../../03-contracts/ui-ux/04-editor-workspace.md) (ownership of undo and drafts). Windows only. Seams versus placeholders rule applies: reusable parts are built and tested with real components, nothing is visible until a feature mounts into them, every seam names its owning later phase in docs/SPRINT-TRACKING.md.
**Write scope:** `app/src/editor/**` (new), `app/src/ui/**` only for a primitive option, `app/src/workspaces/**` and `app/src/nav/**` only to mount the Create shell structure, catalog entries only if a visible control is added, theme tokens through the S02.1 process only if needed.
## Slices
- **S02.5a Docking and split:** `SplitView` (two regions, pointer and keyboard resizable with a separator that has a role, value and keyboard steps, sizes from tokens, persisted only in memory for now) and `DockPanel` (an edge drawer that is collapsed by default, opens on request, becomes an overlay drawer at the tablet width token, focus managed, Escape closes). The Create shell uses them for the structure in doc 12: dominant surface, optional Assets drawer, Inspector region; all collapsed or empty and invisible until a feature mounts.
- **S02.5b Tabs:** `TabStrip` for genuinely simultaneous open documents: overflow handling, keyboard navigation (arrows, Home, End, Delete or close key), close buttons, reorder by keyboard and pointer through the Input Manager, a dirty marker that is text plus shape not color only, roles per the ARIA tabs pattern. Rendered only when there is more than one open document (doc 12: no permanent tabs for modules).
- **S02.5c Inspector container:** `Inspector` and `InspectorField` shell: grouped collapsible categories, field rows with label, value control slot and inline validation message slot per doc 02, appears only when something is selected, empty sections hidden. No schema data and no fake fields: it renders whatever typed field descriptors a feature passes in (the S09 data inspector is the consumer).
- **S02.5d Focus and undo ownership:** one `EditorFocusMediator` usage for panels (focus order across surface, drawer, inspector, tabs; restore on close) and one `DraftUndoStack` owner in `app/src/editor/` (typed command entries with do and undo, bounded size from named configuration, redo cleared on a new command, dirty derived from the stack position vs a saved mark, exposed to the existing leave-impact interface so the Create guard can report unsaved drafts). The Undo, Redo and Save toolbar controls are NOT rendered (no feature yet).
## Acceptance
AC-01 each part is accessible per its ARIA pattern (roles, names, keyboard, focus restore, Escape) and activates only through the Input Manager; AC-02 tokens only, both presets, no literals, no tooltips on ordinary controls; AC-03 SplitView sizes never go below token minimums, keyboard steps and pointer resize agree; DockPanel overlays at the tablet width; AC-04 TabStrip overflow, reorder, close and dirty marker behave and are tested with real components; AC-05 Inspector shows nothing when empty and renders typed descriptors with inline validation; AC-06 DraftUndoStack semantics (do, undo, redo, bounded, dirty vs saved mark) and the leave-impact hook tested; AC-07 the Create shell shows no text beyond the frame row until a feature mounts (inventory test); AC-08 filtered vitest and build green.
