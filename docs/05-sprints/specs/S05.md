## Phase deliverables and exact handoff
Each phase below is a **small stand-alone vertical slice**. One Builder, then one independently scoped Auditor, with a real hands-on demonstration or runnable harness **before** checkoff. Usually more than one phase should be finishable within a single Claude usage window; if unexpectedly broad, Lead splits the phase in the central tracker *before* assigning it.

**S05.1 Command assets** — Deliver: Typed definitions + native defaults. User test: Run look and say. Auditor negative case: Unknown action rejected.

**S05.2 Alias matcher** — Deliver: Longest complete word alias. User test: Use look through window. Auditor negative case: No prefix/confusable shadow.

**S05.3 Typed grammar** — Deliver: Quotes, switches, lhs=rhs. User test: Give "silver key" = "Joe Smith". Auditor negative case: Bad token rejected.

**S05.4 Long arguments** — Deliver: Multiline, schema-bounded command data. User test: Use long builder command. Auditor negative case: No length-based type switch.

**S05.5 Dynamic cmdsets** — Deliver: Session/actor/room/item/exit scopes. User test: Use lantern after pickup. Auditor negative case: No stale cache.

**S05.6 Access rules** — Deliver: Typed permission predicates. User test: Quest-gated action appears. Auditor negative case: No auth bypass.

**S05.7 Ambiguity** — Deliver: Expiring visible-target selection. User test: Pick second key. Auditor negative case: No hidden or expired token.

**S05.8 Single executor** — Deliver: GUI action and text share validation. User test: Move by both interfaces. Auditor negative case: Same authorization.

**S05.9 Event commit** — Deliver: Idempotent command/outbox. User test: Retry give once. Auditor negative case: No duplicate write.

**S05.10 Narration** — Deliver: Observer-projected committed output. User test: Hear bell in right room. Auditor negative case: No private leak.

## Runtime acceptance specifics
- Command kind is explicit at protocol boundary and **not** inferred from length. `CommandText` is one logical invocation, including when the command's declared typed argument permits long/multiline data. `InvokeAction` and console paths share the **same** action ID, authorization, limits and world transaction.
- Use the **machine schemas** for native action IDs, arguments, merge semantics and scopes. Query/help/candidates cannot reveal hidden commands or target IDs. Do not implement dynamic C# evaluation, regex inputfuncs or remote-supplied script/binding names.
- Build parser with a native/focused harness independent of S08 network. The supplied [Evennia crosswalk](../../03-contracts/client-input-v1/08-evennia-research-crosswalk.md) already documents cmdhandler/cmdparser/MuxCommand/cmdsets. **Do not re-research Evennia.**

## Build/test rule
Builder selects the **smallest actual source/test modules** touched by this phase, supplies exact commands, logs and a runnable user check. No fabricated test names or simulator standing in for native functionality. Auditor reviews precisely this scope and one failure path; PASS only when evidence is real and blockers/defects are gone. Lead records commit, test, user check and Auditor PASS in [tracker](../../SPRINT-TRACKING.md), then updates the 0/N count. Do **not** run a full-suite test on each phase; full sprint closeout remains Auditor-controlled.

## Handoff contract
`phaseId; existing module/test paths; approved contract; deliverable and non-goals; targeted tests; user demo; negative oracle; evidence links; known blockers`. Research and unresolved decisions must be completed and written into the linked documentation **before** handoff. No 'research how X works' or 'choose a suitable library' Builder task.
