# S09 — Checkable Phase Deliverables

**Status:** All unchecked/planned. This phase checklist belongs to [main tracker](../../SPRINT-TRACKING.md). This file is **not** evidence of implementation. Each phase is a small finished vertical slice, with a visible demo or reproducible harness, one Builder, and **one independent scoped Auditor**. Check a box only when real deliverable, exact test evidence, user-demo evidence and Auditor PASS are linked in the phase evidence log. No bulk approval across phases; no full suite per phase.

- [ ] **S09.1 — Central ThemeManager** · **Deliver:** Typed theme schema, one token resolver and shared visual harness. **User check:** Change typography/color token once; several panes update. **Auditor:** Auditor checks no hardcoded consumer styles. **Evidence:** pending.
- [ ] **S09.2 — Theme customization** · **Deliver:** Dark default plus save/import/export/preview/rollback. **User check:** Make custom theme, restart editor and reopen it. **Auditor:** Auditor tests malformed imports, persistence, contrast. **Evidence:** pending.
- [ ] **S09.3 — Graph-paper renderer** · **Deliver:** Continuous minor/major square grid lines, pan/zoom/snap. **User check:** Pan/zoom dark graph paper; never dots. **Auditor:** Auditor tests transforms, clipping and HiDPI. **Evidence:** pending.
- [ ] **S09.4 — Editor shell/input** · **Deliver:** Responsive panels, keyboard/touch/pen/focus management. **User check:** Use inspector and search on desktop/tablet. **Auditor:** Auditor checks focus and accessibility. **Evidence:** pending.
- [ ] **S09.5 — Map authoring** · **Deliver:** Real room/cell/region/exit editing with undo and save. **User check:** Paint and connect rooms, then reopen saved project. **Auditor:** Auditor checks asset roundtrip and invalid exits. **Evidence:** pending.
- [ ] **S09.6 — Visual acceptance** · **Deliver:** Cross-editor theme consistency + measured UI responsiveness. **User check:** Creator follows hands-on flow without instructions. **Auditor:** Auditor independently checks usability/performance. **Evidence:** pending.

## Phase handoff / sign-off
For **each** checkbox: Lead writes exact scoped task + accepted contract and test path; assign one Builder to implement, produce focused test output and a usable demonstrator; assign one different Auditor to independently inspect that phase's delta and negative tests; show user the demo as soon as runnable; record feedback/fixes in the same phase and repeat focused audit only for changed code. Lead then commits the verified phase, adds specific evidence link beside the checkbox, and updates progress count in [SPRINT-TRACKING](../../SPRINT-TRACKING.md). **No next phase is marked complete early**, even if another phase has source files. A real blocker remains unmarked until resolved. Builder doesn't run full suite unless specifically authorized under agent governance.
