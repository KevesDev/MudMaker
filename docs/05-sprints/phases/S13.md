# S13 — Checkable Phase Deliverables

**Status:** All unchecked/planned. This phase checklist belongs to [main tracker](../../SPRINT-TRACKING.md). This file is **not** evidence of implementation. Each phase is a small finished vertical slice, with a visible demo or reproducible harness, one Builder, and **one independent scoped Auditor**. Check a box only when real deliverable, exact test evidence, user-demo evidence and Auditor PASS are linked in the phase evidence log. No bulk approval across phases; no full suite per phase.

- [ ] **S13.1 — GUI/headless parity** · **Deliver:** Real launch/stop of one identical release by desktop UI and CLI. **User check:** Start host through either entry; connect client. **Auditor:** Auditor checks manifest/hash and process parity. **Evidence:** pending.
- [ ] **S13.2 — Startup preflight** · **Deliver:** Reject invalid scripts/hook bindings/schemas before accepting clients. **User check:** Break script manifest and see actionable startup error. **Auditor:** Auditor checks no half-running world or player acceptance. **Evidence:** pending.
- [ ] **S13.3 — Persistent restart** · **Deliver:** Restore world, quest, door overrides, timers, outbox and worker. **User check:** Stop/restart during quest; continue progress. **Auditor:** Auditor tests crashes at commit/outbox boundaries. **Evidence:** pending.
- [ ] **S13.4 — Networking/operations** · **Deliver:** Host status, logs, remote join instructions, config/TLS/port validation. **User check:** Another person joins hosted game, sees diagnostics. **Auditor:** Auditor checks auth, port faults and secrets. **Evidence:** pending.
- [ ] **S13.5 — Backup/rollback** · **Deliver:** Reliable snapshots, version restore and error handling. **User check:** Restore prior release/save and confirm content. **Auditor:** Auditor checks incompatible schema and recovery. **Evidence:** pending.
- [ ] **S13.6 — Host walkthrough** · **Deliver:** One-click hosting and headless recovery on supported systems. **User check:** User follows host/play checklist end-to-end. **Auditor:** Auditor verifies actual target environments and final failures. **Evidence:** pending.

## Phase handoff / sign-off
For **each** checkbox: Lead writes exact scoped task + accepted contract and test path; assign one Builder to implement, produce focused test output and a usable demonstrator; assign one different Auditor to independently inspect that phase's delta and negative tests; show user the demo as soon as runnable; record feedback/fixes in the same phase and repeat focused audit only for changed code. Lead then commits the verified phase, adds specific evidence link beside the checkbox, and updates progress count in [SPRINT-TRACKING](../../SPRINT-TRACKING.md). **No next phase is marked complete early**, even if another phase has source files. A real blocker remains unmarked until resolved. Builder doesn't run full suite unless specifically authorized under agent governance.
