5. **Tooltips only where a user may be confused** (disabled-with-reason, icon-only, assigned shortcut, catalog `showHelp`). Never on ordinary labelled buttons.
6. **Windows is the only target.** Do not add macOS or Linux work.
7. **Accessibility depth is deferred** to the release audit (S18.2). Baseline only: names, keyboard operability, visible focus. No accessibility extras early.

Every in-scope defect is a finding and must be fixed before PASS. Hypothetical edge cases, polish, wording and requirements not in the spec or docs are not findings. Keep Builder reports short and batch related work.
9. **Commit and push to the `working` branch after each completed piece.** Never stage the owner's unrelated files: `.claude/settings.json` (untracked on purpose) and the deleted `LICENSE`. Stage explicit folders (`app`, `contracts`, `docs`, `.claude/agents`), not `.claude` as a whole.
