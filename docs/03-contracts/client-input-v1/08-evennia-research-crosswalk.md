# 08 — Deep Evennia Input and Command Research → MudMaker

**Source-derived vs MudMaker decisions:** Evennia behavior below is documented in official manual and inspected in **upstream commit `98b9df21c91b111dda7c51c8ab62f42faf4d9dae` (2026-10-24)**. MudMaker implementation choices are **new designs**, not claims Evennia has a visual command editor, a typed ECS, or these resource defaults. This review covers the **core input, parser, command, cmdset, locks and protocol entrypoints**, not every Evennia contrib/custom game parser.

## Security and UX distinctions
Evennia's extensibility is intended for trusted game developers, not for network clients to send Python modules. Its batch-code processor explicitly warns about severe security risks and limits code execution to superusers. MudMaker's host likewise publishes **local** scripts; ordinary players never upload code. A **visual command editor** is MudMaker's proposed usability improvement over authoring command Python classes and composing lockstrings manually; it should still offer advanced Code/Graph hooks for expert authors.

Evennia is a technical reference for parser features; not a substitute for MudMaker's network security policy. Rate/size/DoS controls are selected from the separate OWASP references and must be independently measured. Avoid assuming Evennia's exact priority order or arbitrary `cmdparser` callbacks are secure defaults for MudMaker.
