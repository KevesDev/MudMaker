# 06 — Built-In Visual Command Creator (No-Code First)

**DECIDED feature UX; not implemented.** Graph and editor typography/colors use [one ThemeManager](../editor-theme-manager.md) and [dark graph-paper canvas](../scripting-v1/06-graph-parity-and-publishing.md). Command editor consumes [typed definition schema](../../../contracts/input/v1/command-definition.schema.json), [parser](04-command-parser-grammar.md) and [access rules](05-command-registry-and-access.md). The interface is built in S09 after S02 editor shell and S04 asset schema; advanced C# / visual graph hooks integrate in S13.

## Creation UX — user can make a command without code
1. Open **Project > Commands > New Command** or inspector **Add Command** on NPC/room/item/exit/quest.
2. Choose template (Say/Emote, Inspect, Interact, Move/Exit, Give, Use, Toggle Field, Dialogue, Quest Command, World Event, Custom Blank); immediately see editable name, example command, and built-in help.
3. **Name & aliases**: plain-language command (may be multiword), shortcuts, optional /switches, case-insensitive matching and collision warning with nearby/default commands. Editor shows *where* command is available, not raw priority integer by default.
4. **Arguments**: add typed fields with accessible forms (required text, number/range, entity reference with visibility/ownership, item in inventory, enum dropdown, schema-bounded multiline argument composer (including long builder/moderator operations)). Preview examples and parsing behavior (quoted names, `lhs=rhs`, whitespace); show command equivalent for graphical button.
5. **When available**: visual permissions/condition builder (Owner, Role, Quest, Region, Item Held, In Room, Exit Docked, etc.) with AND/OR/group; **never unrestricted access/lock code**. Show effective command providers and conflicts. Advanced priority/merge panels for experienced hosts.
6. **What it does**: no-code action builder selects existing registered `GameEffect`s (ShowDialogue, SetComponentField, ChangeWorldEvent, Move via native action, etc.), combines in transaction with error behavior; or opens shared visual graph; or binds a locally published C# method later. All effects pass central native authorization.
7. **Presentation**: help category, usage, autocomplete examples, description, success/error message templates, moderation and action rate class, RP length class and default command visibility.
8. **Try it**: test console and simulated UI button drive **real isolated ECS test world** (not fake parser) showing parser AST, matched source/alias, arg types, role/phase/target access, effect plan and committed outcome. Invalid input displays helpful diagnostics.
9. Save as draft; **Publish** validates alias conflicts, scope/ACL, argument limits, capabilities, graph and C# bindings and world refs; stop host, publish immutable release, restart to deploy.

## Sample no-code creator task
Host wants `ring bell` when near station bell: name `ring bell`, alias `bell`; scope = NearbyObject (station bell), condition = Actor in room AND Bell visible; args = none; action = `EmitDomainEvent(StationBellRung)` and optional `SetComponentField(Bell.LastRungAt)`; help = “Rings the station bell.” Test two players; only those in the proper room see localized event. **No command script required.**

Host wants custom `give item = person`: selected template "Give"; item selector = `OwnedInventoryItem`, target selector = `VisibleCharacter`; split grammar `lhs=rhs`; native `TransferItem` domain action (NOT arbitrary inventory field override). Engine checks original and destination ownership/capacity at commit. Editor validates and displays `give "red key" = "Joe Smith"` syntax.

## Editor structure
Sidebar project command library; central **Command Definition Form**; optional **Graph** tab, using central ThemeManager graph-paper renderer; right Inspector for availability, sample input/parsed output and conflict diagnostics; bottom real Test/Trace/Problems. Accessibility: no hover-only controls, autocomplete and direct keyboard navigation, touch/pen drag alternatives. Show beginner fields first; advanced precedence, connection and ECS capabilities folded away with clear explanations.

## Versioning, accessibility and safety
- Draft content never becomes a live game command until host local publish. Connected players cannot send `CommandDefinition` assets or override command handler bindings.
- Editor **prevents publish** if unknown action type, unsafe capability, conflicting aliases without explicit precedence, invalid input bounds, unknown owner, missing help or target type, circular graph or incompatible release.
- User theme changes the editor, not game command semantics. Visual editor itself does not duplicate `CommandService` or define a second parser.
- `SubmitText` RP composer and character bio editor are first-class GUI forms; the command editor chooses their entry actions but does not squeeze prose into a tiny console line.
- Include a no-code onboarding walkthrough: "Create a command and invite a second player to test it"; measure completion and drop-off, not only feature checklists.

## Complete Command Wizard and management lifecycle — binding UX

**Entry points:** Creator → Commands opens the existing Command Library in Asset Explorer and its central Command Definition editor. "New Command" launches a guided sequence **Choose Starter → Name/Aliases → Inputs/Target → Availability → Action → Player-facing Feedback → Test → Save Draft/Publish**. This is a progressive-disclosure view of the *same CommandDefinition*, not a parallel wizard schema, new editor window, independent rule engine or mandatory full-screen modal. A user may switch at any step to the full editor without losing values, and return to guided mode. A saved draft reopens at the last relevant stage; save/validation are project-persistent. Plain-language field summaries and working examples explain the effect of every choice; "Advanced" exposes canonical IDs, scope/priority policy, graph binding and C# handler with typed SDK docs.

**Manage commands from one library:** searchable list/tree, type/category/scope/tag/status filters, favorites, folders, description, aliases, where-used, revision and author metadata. Every selection opens the same editor. Toolbar and contextual actions: **New, Edit, Rename, Duplicate, Create Variation, Enable/Disable, Archive/Restore, Delete, Where Used, Compare Revisions, Test, Publish**. Commands are reusable versioned project assets compatible with the universal Template Library. Rename preserves CommandId; changing aliases or primary name requires collision revalidation and an explicit publication step. Duplicate generates a new independent CommandId; variation pins the parent command revision and displays inherited/overridden fields. Enable/disable is a published availability policy, not deletion; disabling a command must not leave hidden aliases callable.

**Safe removal:** a draft with no external references can be deleted after Where Used and explicit confirmation. Commands referred to by menus, equipment, NPCs, quests, interactive objects, published command packs or live releases must not be destructively deleted; provide **Disable** and **Archive** with dependency review instead. Removal of a command from an available scope invalidates cached command views and help/autocomplete consistently; previously issued command requests still undergo current host authorization/revision checks. Draft undo never reverts committed live world actions.

**No-code action builder:** start with common actions (say/broadcast, show text/dialogue, move via exit, get/give/put, use item, set/adjust typed attribute, trigger world event, start quest interaction, request inventory/craft transaction). Pick target/argument selectors through human-language controls; display a plain-English summary, e.g. "When a player with permission is next to this bell and types RING BELL, emit the bell-rung event to the room." Multi-step effects use typed graph links and native atomic services; never represent an unsafe sequence of independent debits/writes as an atomic action. Advanced authors may attach a version-pinned graph or published C# handler to the *same* command asset, or replace its no-code action while preserving CommandId/help/permission contract.

**Wizard behavior and errors:** Continue disabled only when the current step cannot be validated, with inline explanation and a direct fix. Back preserves input. Cancel offers Save Draft/Discard/Continue when dirty. Errors from stale revisions or changed permissions preserve form fields, show side-by-side conflict preview and don't silently overwrite. Preview has **Command entered → Resolved alias → Parsed arguments → Access decision → Action preview → Committed result/error** through the real isolated host. Publishing checks duplicate primary names and aliases across co-active scoped command sets, grammar ambiguity, unauthorized effects, missing references, unsafe C# bindings and version compatibility. Explain failures without technical jargon; keep expandable diagnostics for advanced creators.

**Starter content and examples:** built-in command packs offer LOOK, SAY/EMOTE/WHISPER, GET/PUT/DROP/GIVE, INVENTORY, movement, object interaction, quest dialogue, attribute toggle and an Empty Custom command. These are editable templates, never hardcoded limitations. A custom `ring bell` command can be made without C#; a custom `cast arcane ward on target` can use typed targeting/conditions and an advanced graph/C# handler. Aliases, object targeting, permissions and scope use the canonical command parser and [command-alias resolution](../command-aliases-and-resolution.md).

**Integrated UI behavior:** Assets/Templates and Commands use one Project Asset Explorer selection and searchable asset picker. The central tab stays Command Definition with Guided / Full Form / Graph / C# views. Inspector displays effective scope, aliases, inherited overrides, dependency/usage summary, error feedback and published revision; bottom Test/Trace/Problems dock supplies real results. On tablet use a responsive stepper and drawers; support keyboard-only navigation, screen reader stage announcements and visible Help at every step. No isolated Command Wizard panel with its own save/revision state.

**Required acceptance:** create and publish RING BELL without code; rename it without breaking linked item or NPC binding; duplicate and vary it; disable and verify aliases disappear from Help and runtime; attempt referenced delete and get safe Where Used denial; archive/restore; close/reopen project and verify saved drafts, tags and folder; introduce alias collision and resolve it; switch Guided→Full→Graph→C# without losing input; test command through two genuine Player sessions; test narrow touchscreen and keyboard/screen reader; confirm published edits only become available through intended host release workflow.

**Universal command tags:** the Command Library's tag editor uses the same [project-wide tag service](../universal-tags-and-organization.md) as templates, script files, world objects and graphs. Search, tag filters, bulk labeling, rename, merge, archive and persistent saved views are not implemented by a separate command-specific tag collection. Organizational command tags do not affect runtime command permission/availability unless a separate typed gameplay rule explicitly says so.
