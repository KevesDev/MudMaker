# Universal tags and organization — binding contract

**Status:** fully decided product and implementation contract; runtime pending. Every authorable asset and every ECS entity can be tagged. This includes objects, rooms, exits, NPCs, items, components assembled into Blueprints, commands, command packs, C# script files/modules/hooks, graph assets, quests, dialogue, events, abilities, factions, templates, variations, schedules, maps and world systems. Tags are not limited to templates or NPCs.

## Two distinct tag namespaces, one shared infrastructure

**Creator organizational tags** belong to project assets/records and help the editor search, group, filter and manage them. Examples: `work-in-progress`, `forest`, `starter`, `guard`, `needs-review`. They have no gameplay effect, cannot be read by ordinary player clients, and are stored in the project's authoring catalog.

**Runtime gameplay tags** belong to ECS entities or published assets and are explicitly usable by host-authorized gameplay queries and conditions. Examples: `crafting.material.wood`, `faction.cityguard`, `flammable`, `quest.item`. They are authored in the same Inspector with a clearly labeled *Gameplay Tags* section but remain separate from organizational tags; tagging an item `work-in-progress` must not inadvertently make it available to world scripts. A gameplay tag **never grants account/party ownership or bypasses security permissions**. Tags classify; typed attributes hold values; relationship records express membership and permissions; aliases participate in names/command resolution.

## Exact storage model

`TagDefinition`: project-scoped stable `TagId` (GUID), `Namespace` (Organization/Gameplay), display label, normalized unique key, optional description, owner project, revision, creation/change metadata, archived state. Uniqueness is per project+namespace+normalized key, Unicode NFKC/invariant casefold; display spelling is preserved. Default maximum tag key 96 Unicode scalars; no empty/control-character keys. Each assignment is `TagAssignment { TagId, TargetKind, TargetId, TargetRevision, CreatedAt, CreatorRef }` with unique `TagId+TargetKind+TargetId`. Assignment and index updates commit atomically. TargetKind permits all project authoring asset kinds and runtime ECS entity refs; each is version/generation checked. 128 tags per target by default; 100,000 tag definitions per project is supported with paginated indexed access.

Rename changes label/key but not TagId or assignments. Merge tags performs previewed remapping of assignments, deduplication and index update in one transaction. Delete is allowed only after Where Used review; organizational tags can be deleted with their classifications (targets survive), gameplay tags referenced by published graphs/recipes/rules are **archived**, not destructively removed, until no live/published references remain. Archive suppresses new selection without breaking existing published release evaluation. Runtime gameplay tag changes are authorized ECS mutations subject to entity revision, capability rules, event/outbox and deduplication. An untrusted player cannot change either tag namespace.

Indexes: tag→paged targets, target→tags, normalized name/alias→TagId, namespace+kind+tag intersections. Queries use stable sort and opaque cursor, with filters ANY/ALL/NONE and per-type/scope constraints; never enumerate every world entity in an editor or script worker. Search can combine tags with name, type, folder, status, components, revisions and author.

## Complete cohesive Creator experience

In the existing Asset Explorer, Templates view, Commands Library, Script File tree, Graph editor, World Data and all object Inspectors, show one reused **Tags** field with searchable chip input, autocomplete, create-new option and clear Organization/Gameplay category indicator. Selection has Add/Remove/Rename/Open Tag Detail; multiple records support bulk add/remove/replace. A shared **Tags** management view is a filter/management mode of Asset Explorer/World Data, not another floating feature panel. Its list displays usage counts, where-used, namespace, descriptions, rename/merge/archive/delete and indexed result preview. Folder/group is independent of tags: a record can be in one folder but many tags.

Project-wide search and quick asset pickers support tag filters; saved searches and Favorites preserve tag IDs across rename and project restart. Script files get organizational tags on their project file catalog entries—**not** injected comments or altered C# content. Gameplay tag bindings in scripts/graphs are typed TagRefs resolved against published revisions, not freeform strings. Adding a missing tag from an Inspector creates the definition and assignment through one revision-checked transaction with immediate searchable feedback.

The tag editor uses the same theme, forms, dialogs, pending/error feedback, keyboard and touch controls as the existing Editor. On an error it retains selected items and draft metadata. Restoring a project rebuilds search indexes from canonical assignments. Cross-project template import previews tag collisions, maps stable IDs and never imports organizational permissions or publishes tags without validation.

## Graph/C# and native behavior

Read nodes: `Tags.Has`, `Tags.QueryEntities`, `Tags.QueryAssets`, `Tags.Count`; conditions `Any/All/None`. Gameplay mutation nodes: `Tags.RequestAdd`, `Tags.RequestRemove` under native capability/permission checks. Organizational tag changes are Creator-only actions, not remote player gameplay commands. C# SDK uses `TagRef`, `TagAssignmentEvent`, `TagMutationEffect` with a validated native service; published C# never gets a direct project-tag writer or hidden entity lookup. Creator tags are not sent in observer payloads; gameplay tags may be visible only when projection permits. Existing ingredient recipe checks use Gameplay TagRefs.

Create and use gameplay `crafting.material.wood` on two inventory stacks; confirm craft counts only the right material and cannot read an unrelated organizational tag. Try destructive deletion of a published gameplay tag and receive Where Used/Archive alternative. Bulk tag 10,000 assets, query 100,000 tag definitions and 1M entity assignments using indexed pagination. Test malicious client modifications, hidden tag inference, restart/backup/restore, concurrent edits, invalid Unicode and script file tags without source mutation.
