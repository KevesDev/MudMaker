# Local engine control v1

**Status:** Lead-selected implementation contract under the owner's delegated decisions, 2026-10-31. Implementation/verification is phase-specific. **Owner:** native engine control boundary; thin Rust shell owns its one connection/lifecycle. [S03.4 phases](../05-sprints/specs/S03-4-SPEC.md).

## Design review and authority

ADR-001 requires C++20/CMake and pinned vcpkg manifests. ADR-002/003 require the existing ECS and sole native writer. ADR-005 requires a separate engine process and thin Tauri shell. S01.4 supplies proto3, versioned handshakes, bounded length-prefixed local IPC and descriptor freeze rules. S01.6 requires complete opaque 128-bit WorldId plus uint32 index/generation. Reviewed system-boundaries, protocol-and-hosting, security-policy and scripting-v1 decisions/wire-security: editor control is a local owner capability, never a remote player message or a script-worker hook. ADR-008 remote transport/auth/reconnection remains OPEN for S07; no decision here resolves it. No persistence, general account authorization, performance or portability evidence is implied.

Windows transport in S03.4b/c will be one access-restricted named pipe, no listening network port. Shell owns the pipe and verifies the connecting child PID; engine runs one writer loop. Use current-user access restriction and remote-client rejection. Pairing material is fresh cryptographic 32-byte data delivered through an inherited bootstrap handle, never argv, logs or the webview. A successful hello binds that launched child/connection before inspection or mutation. This is local process pairing, not a sandbox against hostile code running as the same OS user. Concrete bootstrap/deadline/shutdown commands and tests belong to the named b/c specs before their implementation.

**Actual process scope:** [S03.4b3](../05-sprints/specs/S03-4b3-SPEC.md) fixes current-logon SID pipe ACL, peer PID/liveness, read-only inherited anonymous credential mapping, absolute partial-frame/Hello deadlines and completion-safe cancellation. Ready idle is not a frame timeout. c still owns the actual Rust parent; b3 native test parent does not imply shell implementation.

## Wire and validation

- Each frame is a four-byte **unsigned big-endian** payload length followed by one binary protobuf Envelope. Zero, over-limit, incomplete/trailing bytes and malformed protobuf reject structurally; transport b/c must check length before allocating its payload. No JSON, alternate encoding, compression or arbitrary method-name dispatch.
- Current envelope version is 1.0. Request IDs are nonzero uint64 correlation IDs, monotonic per connection when the process exists; no automatic replay of mutations. Connection IDs are canonical nonzero opaque 128-bit GUID text. All replies echo request/connection IDs. Hello advertises a minor interval; current supported minor is 0. Major mismatch or no common minor returns structured failure in the future process, with no world operation. This codec accepts current envelopes only. No live event stream/sequence is introduced.
- A shared `protocol-policy.json` supplies initial **local diagnostic safety limits**: frame bytes 1048576, logical value depth 32, aggregate value nodes 4096 and single text UTF-8 bytes 262144. These four are configurable named controls, not benchmark-derived workloads or release performance promises. Logical depth is supported only from1 through32 for the current message nesting. Both languages consume this file; reject invalid limits and prove smaller overrides. Count nested Record/List values across one inspection, including container values. Frame size still bounds metadata. Reject before recursive encode/copy; decoder's protobuf depth/size bounds apply before semantic traversal.
- **Actual dependency constraint / Lead decision:** pinned prost0.14.4 fixes physical protobuf recursion at100 with private context methods and no supported runtime setter (Builder source evidence: encoding.rs41–43 and lib.rs). Keep that guard; C++ explicitly uses100 too. `protobuf_recursion:100` in shared policy is a fixed supported value, not an adjustable knob; reject any other value rather than ignore it. No patched/disabled parser or custom protobuf reader. The logical depth cap32 leaves the current Envelope/inspection/value wrapper path within that physical ceiling; the cross-language boundary oracle must prove the supported deepest current value. Later schema extensions must recheck that nesting relationship in their assigned phase.
- GUID text is lowercase `8-4-4-4-12`, preserving the 16 bytes in display order, not Windows GUID mixed-endian struct layout. No UUID version-bit requirement; zero is invalid. Shared EntityRef's uint64 entity_id must fit native index **below UINT32_MAX**, with generation preserved exactly including zero/max. Asset revision and schema revision must be positive. Representation validation is not a live-reference/authorization check.
- Additive native value boundary: public WorldId::from_bytes reconstructs a reference value only. It must not issue/register a namespace or construct an allocator; IdentityDomain retains that authority. This resolves the Builder-reported private-constructor integration gap. It does not grant incoming IDs existence or authority.
- Explicit Null uses PropertyValue's explicit_null branch with true; false or a missing oneof is malformed here. No absent field becomes Null or zero: Record omission means absent. Reject duplicate FieldIds, malformed IDs, nonfinite floating values, invalid UTF-8, missing typed children and out-of-budget values. Component roots are Records. Native schema/value constraints and live-reference checks stay in the existing S03.2/3 owners, not a second wire schema validator/world.
- Preserve signed64 exactly, including extrema; no JavaScript number conversion. Text, nested Records/Lists and typed references remain owned values. Conversion to/from native SchemaValue must preserve absent/null/present and own its memory. Codec errors are typed and descriptive. No exception swallowing, partial result or truncation.
- Native Record keys are field names, wire keys are stable FieldIds. Conversion reuses the existing immutable component descriptor to map them; it creates no second catalog/validator. Local policy JSON uses protobuf's existing reader in C++ and pinned serde_json1.0.154 in Rust; this configuration parsing is not a transport format.
- Unknown protobuf fields may be ignored for additive evolution; an unknown/missing body/value kind or ErrorCode rejects. Protobuf serialization is not canonical: interoperability compares semantic values, not incidental field ordering/byte equality.
- Commit an initial descriptor set including imports. A substantive compatibility check compares freshly generated descriptors with the frozen set: existing package/message/field names, numbers, types, labels, oneof membership and enum names/numbers stay stable; additions are allowed. Removed fields require reserved names/numbers and an explicitly reviewed breaking version, not silent acceptance. A deliberately changed existing field must fail the checker. Later releases refresh snapshots only after compatibility passes and review. No worker protocol source changes in a.

## Dependency decision and primary evidence

Use vcpkg baseline **9a5dfef5d1a0438a7d24856a85bd60f309d355e9**, verified from Microsoft's remote metadata, with protobuf override **7.36.2** and its **protoc 36.2**. The manifest at that exact commit was read and reports 7.36.2. Build compiler and C++ runtime through that pinned manifest using the C++20 triplet decision below; never use PATH's26.1. Pin Rust **prost/prost-build =0.14.4** with a committed crate lockfile; its build uses the same pinned protoc. Rust is an independent wire codec, not a second engine. Keep it in one reusable `engine/wire-rust` crate for the future shell to consume.

Primary references: [C++ exact-version requirement](https://protobuf.dev/support/cross-version-runtime-guarantee/), [supported C++ release line](https://protobuf.dev/support/version-support/), [protobuf 36.2](https://github.com/protocolbuffers/protobuf/releases/tag/v36.2), [prost 0.14.4](https://github.com/tokio-rs/prost/releases/tag/v0.14.4), [vcpkg manifest versioning](https://learn.microsoft.com/en-us/vcpkg/users/versioning). Interoperability is an execution gate, not assumed from these documents.

**Observed version-label correction:** the pinned port is7.36.2, its upstream CMake package reports36.2.0, runtime_version.h reports PROTOBUF_OSS_VERSION7036002, and protoc reports36.2. Check that exact package label **and** runtime marker/compiler; do not compare unlike labels or relax to an unpinned package. Builder's initial configure failed this label check after dependencies built; the correction changes verification, not pins.

**Actual ABI blocker / Lead decision:** the initial x64-windows runtime built as C++17, exporting protobuf's DynamicInit empty-string ABI; generated C++20 objects require GlobalEmptyStringConstexpr, causing LNK2019 despite matching versions. Preserve required C++20 for authored/generated code and rebuild dependencies consistently. Authorize one `engine/vcpkg-triplets/x64-windows-cxx20.cmake` based on the pinned x64-windows defaults, appending CMAKE_CXX_STANDARD=20 via the supported [VCPKG_CMAKE_CONFIGURE_OPTIONS](https://learn.microsoft.com/en-us/vcpkg/users/triplets#vcpkg_cmake_configure_options). Use it for both target and host triplets, with fresh named build directories; no dependency-source patch, alternate port, compiler downgrade or disabled ABI checks. Preparation/CMake must verify the effective setting and actual link, not assume the option won. Existing ignored C++17 caches remain unused. Any inability of the pinned port to honor this supported option must be reported before another approach.

**ASan ABI refinement:** instrument generated and authored code consistently. Actual ASan linking then exposed protobuf's sanitizer-dependent ClassDataFull/MESSAGE_GLOBALS constructor ABI in conflict with the ordinary runtime. Use the additional x64-windows-cxx20-asan target triplet to build pinned dependencies with ASan too; host protoc remains the separate ordinary C++20 tool. Keep annotations and sanitizer checks enabled. No PROTOBUF_MESSAGE_GLOBALS_TEMPORARY_OPTOUT, source patch or pin change. This profile is local sanitizer verification, not a packaged release or portability claim.
