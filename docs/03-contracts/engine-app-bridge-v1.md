## One managed owner and explicit startup

One Tauri-managed bridge owns/reuses exactly one c1 EngineOwner. `engine_start` is explicit async initial startup/Retry entry: derive trusted Development locator under debug build, resource-root locator otherwise; launch through c1, return actual Ready metadata only after PID/Hello/native World. Concurrent start attempts share/bound the one initialization, never launch duplicates. Failure leaves honest Failed; explicit subsequent Retry may start one NEW empty session/world, never replay prior mutations. `engine_status` is a side-effect-free actual liveness query (no file-presence success). Do not call starting the local empty inspection backend hosting a game or show Active World.

`engine_request` validates typed DTO representation and budgets, submits through c1 nonblocking try_request and waits OFF UI thread; one outstanding admission/Busy, no queue of waiting tasks or alternate IPC. Owner assigns private headers/IDs. Minimal readonly validated Policy snapshot accessor in c1 allowed if needed for one shared budget source, no config reread/defaults or mirrored state. Native ProtocolError is an ordinary typed error RESULT; transport/Busy/not-ready/unknown-outcome are typed bridge failures, not fabricated success/rollback. No automatic reconnect/retry after death.

`quit_app` retains existing frontend routing/leave/host confirmation ownership; only accepted exit stops owner. Shutdown is async/off UI thread through same managed owner, actual Graceful/Forced outcome and bounded cleanup before app.exit. An idempotent final RunEvent::Exit immediate cleanup fallback covers actual OS/app termination. Do not stop owner on merely requested/cancelled exit, add another quit/confirmation route or change WindowShell min/max. An in-progress startup cannot later publish Ready after exit/invalidated attempt; its eventual owner must be stopped, no leak. Existing app setup/webview security/preferences behavior preserved.

Frontend startup explicitly calls startEngine, checks status **ready** rather than installed, sets STARTUP_REQUIRES_ENGINE=true and routes actual startup failure through existing error/log/Retry UI. Normal ready draws no invented engine indicator/status panel; accepted compact/global Theme stays unchanged. App activation is c2, actual Inspector actions are d. No new controls/styles in c2.

## Typed JSON shapes and exact values

All DTO keys camelCase. Reject unknown request/value variants/missing typed fields; no arbitrary JSON-RPC strings. Use real proto types internally, no serde attributes on protobuf messages that silently serialize signed64 as JSON number.

- EntityRef: `{worldId:string,index:number,generation:number}`. index/gen checked uint32, index strictly below UINT32_MAX; world canonical GUID. AssetRef: `{assetGuid:string,revision:number}` positive uint32 revision. ComponentValue: `{componentTypeId:string,schemaRevision:number,value:Value}`; revision positive, root Record. IDs use existing canonical/full-reference adapters.
- Value tagged by `kind`: `null`; `boolean` with boolean value; `integer` with STRING value; `floating` with finite number value; `text` with string value; `entity`/`asset` with typed reference value; `record` with `fields:[{fieldId,value}]`; `list` with `items:Value[]`. Missing Record field is absence, not Null/default. Null is explicit `{kind:'null'}`. Preserve actual FieldIds, nested values and exact signed64.
- Every signed64 value/constraint and every uint64 offset/total/size limit is a canonical decimal STRING. Parse checked range then require to_string equivalence: no fractional/scientific/plus/leading zeros/negative zero/unsafe JS number. uint32 schema/type IDs/generation/index/page limit remain checked numbers. No loss through f64 or JSON number coercion.
- ComponentSchemaInfo mirrors dispatch contract: componentTypeId,schemaRevision,name,persistence (`transient`/`persistent`),display,description,fields,types,placement (`archetype`/`sparse`). FieldInfo: fieldId,name,required,typeId,display,description and optional defaultValue; absent property means no default, explicit Null remains Value null.
- TypeInfo: typeId,kind (`boolean/integer/floating/text/entity/asset/record/list`),nullable,constraints,fields for Record, optional elementTypeId for List. Flat node links and metadata stay actual published serialization views. Constraints integerMin/Max, textMin/MaxBytes,listMin/MaxItems are optional decimal strings; floatingMin/Max optional finite numbers; enumValues typed Value[]. Preserve presence and every native constraint; no new schema validator/default resolver in bridge.

Representation conversion obeys SAME validated policy: limit logical depth/nodes/single-text/whole frame before recursive clone/serialization. Tauri serde recursion itself is not sufficient; reject over-budget typed DTO before native send, no stack or unbounded aggregate bypass. Outgoing native responses already passed codec; mapping retains limits/exactness. TypeScript types are views, never runtime authority.

Request union keyed `op`: catalog/list `{offset:string,limit:number}`; create `{components:ComponentValue[]}`; inspect/destroy `{entity}`; add/replace `{entity,component}`; remove `{entity,componentTypeId,schemaRevision}`; field `{entity,componentTypeId,schemaRevision,fieldId,value}`. No Hello/Shutdown/raw envelope variant from webview. Shutdown belongs app lifecycle.

Response union keyed `op`: catalog `{schemas,total:string,nextOffset?:string}`; list `{entities,total:string,nextOffset?:string}`; created `{entity}`; inspection `{entity,components}`; mutation `{entity}`; error `{code,nativeCode,message,worldId?,entity?,componentTypeId?,schemaRevision?,fieldPath:string[]}`. Code maps existing native ErrorCode explicitly; target/cause retained. Normal rejection is not thrown away as transport failure. Bridge failure `{code,message,outcome?:'none'|'unknown',rawExit?:number}` uses bounded existing native metadata, no secrets/raw payload/argv/path dump. Status `{state:'starting'|'ready'|'stopping'|'stopped'|'failed',worldId?:string,failure?:BridgeFailure}`; publish worldId only for actual current ready session, clear on failure/stop.
