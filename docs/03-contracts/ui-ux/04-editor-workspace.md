# 04 — Creator Editor: complete surface and navigation design

**Owns draft world construction, not remote gameplay.** Every UI element is indexed as a [stable registry item](../../../contracts/ui/v1/INDEX.md). Existing feature specs still own exact map/quest/script domain behavior. UI documents supply navigation, action semantics, visible feedback, and component reuse.

## Editor shell
Top **Project bar**: project name + schema version + dirty/autosave indicator, Save/Save All, Undo/Redo, Validate, Test, Publish (when eligible), View, Search, Help, Account; publish is disabled for invalid changes, with exact Problems panel reference. Sidebar **Asset Explorer**: persistent **Assets / Templates** views within one explorer (not a separate arbitrary panel); both use folders, tags/favorites, indexed search, new/import/duplicate/rename/archive/delete, where-used/dependencies. Template Library uses the same selected-asset Inspector and central Blueprint tabs. Central tabbed workspace: map, Blueprint/component, graph/code, quest/dialogue, world systems, commands. Right **Inspector**: typed fields, permission/revision, override origin and reset. Bottom dock: Problems, Test Output, Execution Trace, Server/Build logs and Help. Panels are dockable/collapsible with saved per-user workspace layouts; mobile/tablet use drawers and visible explicit toolbar buttons.

## Project Template Library — planned first-class Editor workflow

**Placement:** The Template Library is the **Templates view of the existing Asset Explorer**, not a standalone unowned dock or a panel bolted onto NPC Studio. The global Project bar **Search** indexes both Assets and Templates with a scope selector. The same central workspace tabs open any template in the Blueprint/graph/asset-specific editor; the right Inspector displays inherited fields, origin/overrides, tag/folder, pinned revisions, validation and Where Used; the bottom Problems dock lists broken links, schema conflicts and publishing errors. A quick **Template Picker** is the same searchable filtered explorer presented contextually during Map Place, NPC creation, Item/Inventory creation, Combat, World Systems and Quest/Dialogue editing. It preserves the originating editor selection and returns after placement, without an extra navigation stack.

**Entry/exit flows:**
1. **From scratch:** Create object in any editor → configure → **Save as Template** (name, folder/tags, duplicate-name warning, dependencies preview) → save draft to project → searchable in Templates immediately. Original placed instance stays in the world.
2. **From library:** Select Templates in sidebar → search/filter/tags/folder → select result → Inspector shows details, lineage and Where Used → **Use Template / Place** into invoking editor → independent instance with pinned source revision. If invoked from the global sidebar, ask for an appropriate destination only if the asset requires placement.
3. **Variations:** Open parent template → **Create Variation** → child draft with parent revision pinned; clearly display **Inherited / Overridden / Removed** fields and Reset to Inherited control. Editing parent draft never silently changes a child or live instance. **Variation Diff / Rebase** previews conflicts, field changes and migration before explicit apply.
4. **Maintenance:** Rename, favorite, tag, move to folder or archive from library context menu/multi-select toolbar. Folder/tag changes are nonbehavioral metadata and preserve stable IDs. **Delete** first opens **Where Used** and a confirmation stating references; referenced/published revisions cannot be destructively deleted. Archive is the offered alternative. Selection, scroll, search and open tabs remain stable after rename/move.
5. **Project roundtrip:** close/reopen project → library opens with saved filters, folder expansion and prior workspace layout; all template IDs, drafts, tags, parent pins and references are reloaded from the embedded project store. Import/export and backup/restore use project service and show dependency/ID collision previews.

**Visual states and reuse:** Templates view reuses the existing Asset Explorer virtualized list/tree, search/filter controls, selection model, breadcrumbs, contextual actions, Inspector, diff/confirmation dialog, toast and Problems dock. No new widget toolkit or parallel TemplateService UI. Provide list and optional tile view; default is indexed list (100k items supported without client-wide load). Every action has semantic `ui.editor.template*` routing through `EditorIntentRouter` and a stable `UI-editor-templates-*` test ID in [editor control catalog](../../../contracts/ui/v1/editor-controls.v1.json), defined alongside [action registry](../../../contracts/ui/v1/actions.v1.json). On narrow/touch layouts, Assets/Templates is a visible top-level switch in Explorer drawer with reachable Save as Template and Create Variation actions. The keyboard command palette and contextual menus expose the same actions. Inline validation, pending/error, dirty/undo, source revision and permission feedback follow shared state rules.

**Acceptance:** Open a real project, create an NPC and chest, save both as templates, tag and group them, make a child variation, place two instances, rename parent without changing their instance names, inspect Where Used, archive/restore, attempt referenced deletion and see safe denial. Close/reopen and repeat search. Exercise keyboard, screen-reader and touch. The same workflow must work for a room, item, world-system definition and custom ECS Blueprint; never hide template saving behind NPC-only UI.

## Tool transitions
- Create map room -> select room -> Inspector typed fields -> Add component/Blueprint -> graph/code binding -> validation -> isolated preview -> publish -> Host (explicit window transition). Every path returns to prior selection and preserves scroll position.
- Selecting a quest NPC in map -> link to Dialogue stage and back (stable asset IDs), same runtime quest data not duplicate editor caches.
- View > Show/Hide Panel, Reset Workspace, Save Layout; no invisible-only panel controls, no conflicting float/resize state.
- Two editors open same project: optimistic revision conflict with inspect/diff/merge, no last-writer-wins surprise. Undo applies draft authoring transactions, never multiplayer committed gameplay.
- Disabled Publish: tooltip names errors and Problems link; disabled Add Exit: tooltip identifies no selected source room; destructive delete shows impact count/affected refs and restore.

## Visible copy and accessibility
Text is localized through semantic label/help keys and action registry. Tooltips always have focus/tap Help equivalent. Each inspector field includes label, units/type, origin/default/revision, validation message and override/reset button when writable. Code editor and freeform descriptions own text focus; global map/graph hotkeys must never fire during composition. Confirmation and async states reflect real owner-service results, and errors preserve user data.
